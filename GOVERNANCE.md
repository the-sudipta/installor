# Governance

Installor currently uses a maintainer-led governance model appropriate to an early-stage research and engineering project.

## Roles

- **Maintainer:** sets release scope, reviews security and architecture changes, manages repository settings, and has final merge authority.
- **Contributors:** propose, implement, document, test, and review changes under the repository license and community policies.
- **Users and research collaborators:** provide reproducible requirements, evaluation evidence, and domain feedback without gaining automatic decision authority.

The current repository maintainer is the verified GitHub account [`@the-sudipta`](https://github.com/the-sudipta).

## Decisions

Routine changes are decided through issues and pull requests. Decisions affecting credentials, process execution, data ownership, licensing, compatibility, or research claims require explicit maintainer review. Significant decisions should record alternatives and verification evidence in repository documentation.

## Releases

The maintainer approves versions and publishes releases after the version, changelog, citation metadata, test results, artifacts, and checksums agree. Platform support claims must distinguish automated coverage from real-hardware validation.

## Evolution

If sustained contributions develop, governance may evolve toward multiple maintainers and documented voting or review thresholds. Any change will be proposed publicly and recorded in this file.
